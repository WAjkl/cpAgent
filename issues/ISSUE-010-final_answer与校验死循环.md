# ISSUE-010 LLM 习惯性调用 final_answer 工具 + 证据校验死循环

- **日期**：2026-08-13
- **状态**：✅已解决
- **影响**：高（推荐场景多次卡到 max_steps 超时）

## 现象

1. LLM 查完所有配件后，习惯性输出 `action: "final_answer"`（不存在的工具）→ 循环提示重试
2. 证据校验把「预算 8000 / 合计 7780 / 差价 390」误判为无法回溯的价格，要求 LLM 修正；
   LLM 在修正回答时把解释文字（含这些数字）又写进 answer → 再次校验失败 → **死循环直到 max_steps**

## 根因

- LLM 训练习惯：很多 Agent 框架有 final_answer 结束工具，DeepSeek 沿用了这个习惯
- 证据校验逻辑过严：预算/合计/差价是**计算值**或**用户需求值**，不是工具返回，被误判为幻觉
- 校验失败后的"让 LLM 改"策略在 DeepSeek 上效果差（它把校验提示当回答对象，越改越乱）

## 解决方案

1. **prompt 明确**："没有 final_answer 之类的结束工具——配件查完后直接输出 answer"
2. **校验白名单**：用户预算（extra_known）与证据价格全和（合计）纳入已知集合
3. **重试上限 1 次**：校验失败最多提醒 1 次，仍失败则放行 + 在回答尾部追加审计标注
   （`> ⚠️ 审计提示：以下数字未回溯到工具返回……`），unmatched 进 trace 供 M4 对抗测试审计
4. **工具不存在提示增强**：明确告诉 LLM"没有 final_answer，直接输出 answer"

## 设计原则变更

证据校验从「拦截」改为「监控 + 审计」：
- M1 目标是"可回溯回复"——价格必须能追溯到工具返回（防止编造价格）
- 但预算/合计/差价等**计算值**不应拦截——它们是用户需求或算术结果，不是幻觉
- 真正的幻觉检测（编造型号价格）在 M4 对抗测试集做回归

## 教训

- LLM 的"结束习惯"要用 prompt 明确纠正，不能靠报错循环
- 校验器要区分「幻觉」与「计算值」，过严的校验会制造死循环
- 让 LLM 反复"修正"不如"放行 + 标注"：审计留痕比无限重试更务实
