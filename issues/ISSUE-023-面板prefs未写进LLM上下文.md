# ISSUE-023 面板 prefs 只静默注入工具参数，LLM 看不到 → 反问已选信息

- **日期**：2026-08-13
- **状态**：✅已解决
- **影响**：高（用户面板选 18000 预算，说「根据我的预算推荐」，agent 仍反问「请提供预算」，并带出上一轮举例数字触发审计提示）

## 现象

面板选 18000 预算 + 游戏 + 联网，发「根据我的预算给我推荐配置」，agent 回复：
- 「请提供您的实际预算金额和主要用途」
- 附带「审计提示：15000 元未回溯到工具返回」（15000 是 LLM 上一轮举例的假设值）

## 根因

ISSUE-013 只解决了「prefs 传送到后端」，但 prefs 在 agent_loop 里**只用于 `_apply_prefs_to_args`（工具参数静默注入）**，从未写进给 LLM 的 system/user 消息。LLM 做决策时看到的只有原始文字「根据我的预算给我推荐配置」，**不知道面板选了 18000**，于是反问预算；多轮里还残留上一轮自己举例的 5000/8000/15000，被证据校验判为「无法回溯」追加审计标注。

## 解决方案

`agent_loop.run` 构建 messages 时，把面板偏好拼接成提示附加到 user 消息：

```
[用户已通过面板选定] 预算 18000 元；用途 游戏；分辨率 2K；联网模式。请直接据此生成/回答，不要再询问这些信息。
```

新增 `_build_prefs_hint(prefs)` 方法，把 budget/use_case/resolution/exclude/mode 拼成中文提示。

## 验证

面板 18000 说「根据我的预算推荐」→ 工具链 `['generate_config']`，回答开头「根据您的预算（18000元）…总价 14900元」，不再反问、无审计提示。smoke 3/3 回归通过。

## 设计原则

- prefs 传递的闭环是「传到后端」→「写进 LLM 上下文」两步，只做第一步等于没做
- 面板选的信息是「明确事实」，必须让 LLM 显式看到，不能只靠工具参数静默注入兜底
