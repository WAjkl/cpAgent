# cpAgent 技术实现与踩坑记录

> 这不是功能说明书。这份文档记录的是：**每个技术选型当时为什么这么选、放弃过什么、以及踩过的坑和修法。**
> 面试时如果有时间只讲三件事，就讲第五章的三个坑——那是编不出来的部分。

---

## 一、项目定位（一句话）

**把「人说一句模糊需求」变成「一张可核对的配置单」的 Agent**，重点不在"能生成"，而在**生成的每一项都能追溯到来源、且花钱的动作必须人批**。

它要回答三个问题：
1. 为什么这个配置是合理的？（可解释）
2. 这个价格从哪来的？可信吗？（可追溯）
3. 如果它要下单，谁批准了？（可控）

---

## 二、技术栈与选型理由

| 技术 | 用来做什么 | 为什么选它 | 放弃了什么 |
|---|---|---|---|
| **FastAPI** | 后端 API + SSE 流式 | 自动生成 OpenAPI 文档（`/docs` 能直接点着测），Pydantic 校验省掉手写参数检查 | 相比 Flask 学习成本略高；同步生态不如 Django 全 |
| **Pydantic** | 请求/响应模型、工具参数校验 | 校验失败自动 422，字段约束声明式（`Field(ge=1, le=5)`） | 复杂嵌套模型写起来啰嗦 |
| **React 18 + TypeScript** | 前端界面 | TS 让接口字段改名在编译期就报错，不用等运行时 | 相比 Vue 上手慢，样板代码多 |
| **Electron** | 打包成桌面应用 | 复用同一套 React 代码，不用为三平台各写一套 | 包体积大（约 150MB），内存占用高 |
| **Zustand** | 前端状态管理 | 比 Redux 轻，没有 action/reducer 样板 | 生态和调试工具不如 Redux 成熟 |
| **SQLite** | 证据库 / 长期记忆 / 审计 | 单文件、零部署、事务完整。个人项目上 MySQL 是负担 | 并发写能力弱，不适合多实例 |
| **urllib（标准库）** | 调 LLM API | 不想为一次 POST 引入 requests 依赖（虽然后来还是用了） | 要自己处理编码、超时、错误码 |
| **手写 ReAct 循环** | Agent 决策 | 为了控制失败路径——工具白名单、三道闸、降级行为都得自己定 | 失去了 LangChain 的现成组件和生态 |
| **正则 + 位置切段** | 抓中关村在线价格 | 零依赖、不引反爬库 | 依赖页面结构，站点改版就要修 |

### 一个明确的取舍：为什么不用 LangChain

短答：**因为我要控制失败路径。**

长答：LangChain 的 `AgentExecutor` 把"出错时怎么办"藏在框架里——工具报错会重试几次？参数不对会怎么处理？循环上限在哪设？这些在框架里是配置项，在我的场景里是**必须自己定死的策略**。

比如「工具返回空结果」这件事，框架通常当成普通返回继续往下走，但我的场景要求：空结果必须让模型知道"这条路走不通"，并重试别的工具，而不是拿空数据硬生成配置单。

代价是失去了生态。**如果只是快速验证一个想法，我会直接用框架；但只要涉及"每一步要可解释、失败要可控"，就得自己写。**

## 三、架构与数据流

```
用户输入（"8000 打游戏 2K 不要显示器"）
    │
    ├─ ① 偏好提取 ──→ WorkingMemory（预算/用途/分辨率）
    │                   ↑ 这里是"确定性注入"的源头
    │
    ├─ ② ReAct 循环（最多 12 步）
    │      ├─ 让 LLM 决定：调哪个工具 / 还是直接回答
    │      ├─ 工具调用前：风险闸（只读直接跑 / 可逆写通知 / 不可逆挂起）
    │      ├─ 工具返回 → evidence 落盘（原文）+ 净化 + 摘要进上下文
    │      └─ 每步都记审计（token/成本/耗时）
    │
    ├─ ③ 确定性拼装 ──→ 配置单由算法拼，模型只出参数
    │
    └─ ④ 输出校验 ──→ 回复里的价格必须能回溯到 evidence，否则标幻觉风险
```

**三层落盘，各管一件事**：

| 库 | 存什么 | 回答什么问题 |
|---|---|---|
| `evidence.db` | 每次工具调用的**原始返回** | 这个价格从哪来的？ |
| `longterm_memory.db` | 用户偏好、历史配置 | 上次配的是什么？ |
| `audit.db` | 每次 LLM 调用的 token/成本 + 每个高风险动作的审批 | 花了多少钱？谁批的？ |

## 四、五个核心机制

### 4.1 ReAct 循环（手写 168 行）

**做什么**：让模型"想一步 → 调一个工具 → 看结果 → 再想"，直到能回答。

**关键设计**：
- **工具白名单**：只有 `registry` 里注册过的工具能被调用。模型说调 `delete_all` 会直接被拒，并被告知"没有这个工具"
- **步数上限 12**：实测 12 步够覆盖正常需求；超了说明模型在绕圈，中断比继续烧 token 好
- **失败要让模型看见**：工具报错不是静默跳过，而是把错误信息回灌给模型，让它换参数或换工具

**为什么不交给框架**：见第二章末尾。

### 4.2 确定性拼装（这个项目最重要的设计）

**问题**：LLM 会编型号、会算错价格。

**错误做法**（我第一版就是这么干的）：让模型直接输出整张配置单 JSON。结果是——同一需求跑 5 次给 5 个不同配置，有时预算 8000 配出 9200，理由是"觉得可以超一点"。

**正确做法**：**改架构，不是改提示词。**

```
模型负责：决定"选哪个档次"（游戏为主 / 要 2K / 预算 8000 → 告诉算法这些约束）
算法负责：从硬件库里按约束挑件、算总价、做兼容性校验
```

模型的输出里**根本没有价格字段**，它想编也没有地方编。

**效果**：同一需求连跑 5 次结果完全一致，8000 预算实配 7875。

**这个思路可以迁移**：任何"模型不该碰的关键值"（金额、库存、权限）都应该从模型输出里拿掉，改成从可信源取。

### 4.3 三道闸（成本与失控控制）

| 闸 | 防什么 | 怎么设 |
|---|---|---|
| 步数 | 无限循环 | 12 步上限 |
| token 预算 | 单次会话烧穿 | 累计 token 超阈值强制收尾 |
| 重复调用 | 反复调同一个工具 | 检测「同工具 + 同参数」重复，回灌提示 |

### 4.4 证据链（可追溯）

**机制**：每次工具调用，原始返回完整落库；上下文里只放摘要（省 token）；最终回复里的每个价格数字，都要能回溯到 evidence 记录。

**输出校验怎么做的**：从回复里正则提取所有价格数字 → 逐个查 evidence → 找不到来源的标 `hallucination_risk`。

**局限（要说清楚）**：这个校验只能抓"无中生有的数字"，抓不到"张冠李戴"（把 A 配件的价格安在 B 上）。要做后者需要更细的引用标注，我没做。

### 4.5 审计 + 渐进式自主（2026-10 新增）

**动因**：查了行业数据——79% 企业经历过 AI 成本超支，Gartner 把全链路审计列为企业级 AI 的准入门槛。个人项目也得有这套，否则永远是 demo。

**两个设计决定**：

① **用 `contextvars` 传 trace_id**，而不是层层传参
```python
# agent_loop.run() 开头设一次
set_trace(session_id, turn_id)
# llm.py 深层调用直接读
ctx = current_trace()
```
好处：`llm.py` 完全不知道审计的存在。这是"切面"的思路。

② **审计失败全部 try/except 吞掉**
记账不能成为业务的单点故障。这是生产系统常识，但很多实现会在这里把主流程拖死。

**渐进式自主三档**：

| 风险级 | 行为 | 例子 |
|---|---|---|
| `read` | 直接执行 | 查硬件库、搜价、抓网页 |
| `write_reversible` | 执行 + 审计留痕 | 生成配置单、刷新价格缓存 |
| `write_irreversible` | **挂起，等人批** | 下单、支付、对外发送 |

**为什么必须是代码约束不能靠提示词**：提示词是"求模型别乱来"，模型输出一次错误的 action，钱就花出去了。硬约束是"这个动作在执行前就被拦住，模型无从绕过"。

## 五、真实踩坑记录（这部分最能说明问题）

### 坑 1｜四个不同的 CPU 被算成同一个价格

**现象**：写了个价格采集器，跑完发现 9950X3D、9900X3D、9800X3D、7800X3D **四条的价格全是 2199**。

**我以为是**：数据源有问题。

**实际是**：我的型号匹配算法只比"词元重叠"——这四个型号里都有 `x3d` 和 `amd ryzen`，重叠度都很高，全被匹配到列表页里第一个 `x3d` 产品。

**怎么修的**：加一层**型号编码硬校验**——用正则提取 `9950x3d` / `9070xt` / `265k` 这种"数字+字母后缀"的编码，要求两边编码集合互相包含，否则直接判 0 分。

**学到**：字符串相似度匹配在型号这种"只差几个字符但完全是两个产品"的场景里**不可靠**。必须有领域规则的硬约束兜底。

### 坑 2｜两个不同的显卡拿到同一个价

**现象**：修完坑 1 后，RX 9070 和 RX 9070 XT 又变成同价了。

**实际是**：每个待匹配项"各自挑最像的"，导致**同一个源商品被重复使用**——两条都挑了列表里那个 7299 的 9070 XT。

**怎么修的**：改成**全局贪心一对一分配**——先算出所有候选对，按分数降序分配，用两个集合记录"已用过的待匹配项"和"已用过的源商品"。

**学到**：**匹配是个分配问题，不是检索问题。** 每条各自最优 ≠ 全局最优，这个思维转换花了我一会儿。

### 坑 3｜海外价当国内价，价格虚高 2 倍

**现象**：项目自带的 `refresh_live.py` 跑完，RTX 4080 Super 从 8499 变成 **25681**（+202%），SSD 从 749 变成 1597。

**我以为是**：抓取解析错了。

**实际是**：看它的文档才发现——GPU 来自 videocardprices.com 的**美元全球街价（含 eBay 二手）**，其他配件来自 techpartprices.com 的 **Amazon UK 含税英镑价**。这些是海外价，比国内实际售价高 1.5–3 倍。

**我先试的错方案**：加一个 1.8 倍的合理性窗口，超出就拒绝。结果 RTX 5090 还是被改成 49734（国内约 1.6–2 万）——因为 GPU 类内部比率从 0.33 到 0.78 毫无规律，**混了不同渠道，没法用统一系数折算**。

**最终方案**：完全禁用海外源的覆盖，改为抓**中关村在线的国内参考价**；同时把所有口径写进 `meta.price_warning`。

**学到**：**接入外部数据前必须先验证量级，不是验证格式。** 格式对但量级错的数，比没有数据更危险——因为它看起来是对的。

### 坑 4｜正则被嵌套标签截断，48 条数据只抓到 1 条

**现象**：抓中关村 SSD 页面，其他品类都能解析 48 条，SSD 只解析到 1 条。

**我以为是**：页面结构不一样。

**实际是**：我用的是 `<li[^>]*data-follow-id="p\d+"[^>]*>(.*?)</li>` 这种非贪婪匹配，而卡片**内部还有嵌套的 `<li>`**，非贪婪直接在内层 `</li>` 处截断了。

**怎么修的**：不用 `</li>` 做边界，改成**先找出所有 `data-follow-id` 的位置，按位置切段**——第 i 个卡片 = 从第 i 个位置到第 i+1 个位置。

**学到**：**用正则处理 HTML 时，不要依赖"闭合标签"做边界**，尤其是嵌套结构。基于位置切段比基于标签配对稳得多。

### 坑 5｜中文全变乱码

**现象**：解析出来的品牌是「铭�u」，应该是「铭瑄」。

**实际是**：用 `gb2312` 解码。gb2312 字符集比页面的实际编码小，遇到生僻字会失败。

**怎么修的**：改成 `gb18030`（gb2312 的超集，覆盖更全），并加 `errors="ignore"`。

**学到**：处理中文老站点，**gb18030 是更安全的选择**——它能解 gb2312 和 gbk 的所有字符。

### 坑 6｜Electron 起不来，报 `ipcMain` 是 undefined

**现象**：`npm run dev` 后窗口不弹，日志报
```
TypeError: Cannot read properties of undefined (reading 'handle')
    at electron.ipcMain.handle(...)
```

**我以为是**：Electron 版本不兼容或安装坏了。

**实际是**：日志最后一行写着 `Node.js v20.18.3`——**它根本不是 Electron 在跑，是 Node 在跑**。环境里有 `ELECTRON_RUN_AS_NODE=1`，这个变量会让 electron.exe 退化成纯 Node，此时 `require('electron')` 返回的是路径字符串而不是 API 对象。

**怎么修的**：启动前 `unset ELECTRON_RUN_AS_NODE`。

**学到**：**看错误要看到最后一行**。前面几行都在误导我往"版本问题"上想，最后一行 `Node.js v20.18.3` 才是真线索——Electron 运行时不会打印这行。

### 坑 7｜后端明明在跑，前端连不上

**现象**：`netstat` 查 8765 是空的，以为后端没起。

**实际是**：**后端端口是 8766，不是 8765**。代码注释里写着「本机 IDE 面板进程常驻占用 8765，若坚持默认端口会 bind 失败」。

**学到**：**先读注释再查端口。** 这个坑浪费了我十几分钟在怀疑"服务是不是崩了"。

### 坑 8｜深分页优化，EXPLAIN 显示「不可能的条件」

**现象**：做深分页压测，`EXPLAIN` 显示 `Impossible WHERE`，我一开始以为优化成功了（查询被优化掉了嘛）。

**实际是**：我传的偏移量算成了负数（表只有 30 万行，我减了 80 万），查询根本没执行。

**怎么修的**：先 `SELECT MAX(id)` 拿真实边界，再算偏移；每次压测都校验返回行数对不对。

**学到**：**性能对比之前，先确认查询真的跑了。** 一个"看起来很快"的结果，可能只是因为它什么都没做。

## 六、已知不足

诚实列出来，面试被问到能主动说，比被问出来强：

| 不足 | 影响 | 如果要做怎么改 |
|---|---|---|
| 价格数据覆盖不全 | 90 条型号里只有少数能自动更新，列表页展示的是热门款 | 接京东商品页（要解决型号→item id 映射） |
| 输出校验只查"无中生有" | 抓不到"张冠李戴" | 做细粒度引用标注（每个数字带 evidence id） |
| 没有真评测集 | 换模型/改提示词无法量化好坏 | 建 30 条用例 + CI 门禁（已列入 P0-3） |
| 单实例、无并发设计 | 多人同时用会互相影响 | 加会话隔离 + 连接池 |
| 无鉴权 | 只能本地跑 | 加 API Key 或 JWT |
| 前端无自动化测试 | 改 UI 靠手点 | Playwright 冒烟 |
