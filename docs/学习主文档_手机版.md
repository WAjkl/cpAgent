# 第 0 章：先看清你的项目到底做了什么

## 0.1 三个项目，各一句话

| 项目 | 一句话 |
|---|---|
| **cpAgent** | 说一句需求，出一张能追溯的配置单 |
| **告警系统** | 3000 条告警压成 40 个事件，再判断哪些是真攻击 |
| **校规问答** | 校内 34 份制度做成可溯源问答 |

**三个项目的共同点**：都不是训练模型，都是**把模型做成能用的系统**。

## 0.2 cpAgent 的完整链路（背这张图就够）

```
你说「8000 打游戏 2K」
    ↓
提取约束（预算/用途/分辨率）→ 存进工作记忆
    ↓
ReAct 循环（最多 12 步）
    ├─ 模型决定：调哪个工具
    ├─ 工具返回 → 原文落库 + 摘要进上下文
    └─ 每步记审计（token/成本）
    ↓
算法拼装配置单 ← 价格从这里取，不从模型取
    ↓
兼容性校验 → 输出
```

**这张图里藏着全部 10 个决策。** 下面一个个讲。

## 0.3 全项目最重要的一句话

> **模型不碰价格。**

因为：模型会编型号、会算错价。**既然它会错，就别让它碰。**

而这一句，就是下面第 1 张决策卡。

## 卡 1｜配置单不让模型拼

**选了什么**
模型只输出参数（预算、用途、档次判断）。配置单由算法从硬件库拼。**模型输出里没有价格字段。**

**为什么不选别的**
第一版我让模型直接输出整张配置单 JSON。

结果：**同一需求跑五次给五个不同结果**，有时 8000 预算配出 9200，理由是「觉得可以超一点」。

我先试了提示词约束（加「严格不要超过预算」）——**没用**。

后来才想明白：**这不是提示词的问题，是架构的问题。** 我把价格从模型输出里彻底拿掉了，它想编也没地方编。

**代价**
灵活性下降。模型本来可能配出一些奇怪但合理的组合，现在被算法约束住了。

**能答哪些题**
怎么防幻觉 / 架构为什么这样分层 / 模型负责什么 / 怎么保证结果一致 / 你和别人的 Agent 有什么不同

**如果只能记一句**
> 提示词是「求它别犯错」，架构是「让它没机会犯错」。

---

## 卡 2｜步数上限设 12

**选了什么**
ReAct 循环最多 12 步，超了中断。

**为什么不选别的**
实测正常需求 5–8 步就够（提取偏好 → 查 2–3 次库 → 生成 → 校验 → 回答）。

12 留了余量。**超过 12 步基本说明它在绕圈**——这时候继续只会烧 token，不会变对。

**代价**
少数复杂需求可能被截断。

**能答哪些题**
为什么是 12 / 循环调不停怎么排查（这是排查的第一依据）/ 怎么控成本

**如果只能记一句**
> 超步不是「不够聪明」，是「没在收敛」——调高上限只是让它烧更多钱。

---

## 卡 3｜上下文只放摘要，不放工具原文

**选了什么**
工具返回的原文完整落库（证据），但**进模型上下文的只有摘要**。

**为什么不选别的**
查一次硬件库返回 20 条带完整规格的记录，几千 token。而模型决策只需要知道「有哪些型号、什么价位」。

**摘要能省 80% token。**

**代价（这张卡最重要的部分）**
**摘要可能丢关键信息。**

比如查回 20 条、摘要只留 5 条，模型可能以为「只查到 5 条」或者「没查到我想要的」，于是再查一次——**这就会造成重复查询甚至循环。**

**这是我自己设计里的真实风险点。**

**能答哪些题**
怎么控成本 / Agent 循环调不停（这是排查方向二）/ 长对话怎么处理 / 摘要的风险

**如果只能记一句**
> 摘要省了 token，但可能让模型误判「有没有结果」——所以摘要必须保留「查到几条」这个信号，不能只给前几条。

## 卡 4｜三个 SQLite 库分开

**选了什么**
三个独立库：证据（evidence）/ 记忆（longterm_memory）/ 审计（audit）。不是一个库三张表。

**为什么不选别的**
三者读写模式完全不同：

- **证据**：大字段（一条几 KB）、只追加、按会话整批取
- **记忆**：小字段、读多写少、按用户找
- **审计**：高频追加、要 `GROUP BY` 聚合

**混在一张表里，索引会互相打架。** 而且 SQLite 一页 4KB，大字段会把热点数据挤出缓存。

**代价**
跨库查询麻烦（要查两次再合并），事务不能跨库。

**能答哪些题**
存储怎么设计 / 为什么不用 MySQL / 查询场景 / 写入压力 / 数据会不会一直涨

**如果只能记一句**
> 分库不是因为数据多，是因为**三种数据被访问的方式不一样**。

## 卡 5｜LLM 做成可插拔

**选了什么**
抽象基类 + 三个实现（DeepSeek / 本地 Ollama / Mock），一个配置项切换。

**为什么不选别的**
三个理由，每一个都是真实的：

- **换模型是一年内必然发生的事**（价格、能力、可用性都在变）
- **测试需要 Mock**（不然每次跑测试都花钱、都依赖网络）
- **本地开发用 Ollama**（不烧钱、离线可用）

**代价**
抽象层会削掉各家的特殊能力（比如某个模型的特有参数传不进去）。

**能答哪些题**
可插拔怎么设计 / 新增模型改哪里 / 怎么测试 AI 功能 / 模型选型

**如果只能记一句**
> 换模型改一行配置，业务代码不动——这就是抽象层的全部价值。

---

## 卡 6｜工具白名单 + 风险三档

**选了什么**
两层：

- **白名单**：只有注册过的工具能被调用
- **风险三档**：只读直接跑 / 可逆写跑完留痕 / **不可逆写挂起等人工批准**

**为什么不选别的**
两层挡的东西不一样：

- 白名单挡「模型幻想出不存在的工具」
- 风险分级挡「模型调了不该自主执行的动作」

**第二层必须是代码约束，不能靠提示词。** 因为提示词只是「求它别乱来」，而模型只要输出一次错误的 action，钱就花出去了。

**代价**
不可逆动作要人工介入，牺牲自动化程度。

**能答哪些题**
工具权限怎么限制 / 白名单怎么实现 / 多用户怎么改 / Agent 的安全边界 / 为什么要人工确认

**如果只能记一句**
> Demo 里「能自动完成」是卖点，生产环境里「自动完成了不该做的」是事故。

## 卡 7｜工具原始返回完整落库（证据链）

**选了什么**
每次工具调用的**原始返回**整段落 SQLite。回复里的价格要能回溯到证据。

**为什么不选别的**
两个用途：

- **能查**：用户说「这价格不对」时，翻出原始返回对账
- **能验**：从回复里提取价格数字，逐个查证据，**查不到来源的标幻觉风险**

**代价**
存储涨得快（每条几 KB），写库有开销。

**能答哪些题**
怎么防幻觉 / 怎么溯源 / 用户投诉价格不对怎么查 / 存储设计 / 「日志对但结果错」怎么排查

**如果只能记一句**
> 不存原文，用户投诉时你根本没法查——只能道歉。

---

## 卡 8｜审计记账，单价可配置

**选了什么**
每次 LLM 调用落一行：模型、token、成本、耗时、成败。**单价做成配置项。**

**为什么不选别的**
企业最怕的不是模型不聪明，是**调用不可见**——花了多少钱、谁花的、为什么这么贵，全说不清。

**单价必须可配置**：模型价格会变，写死的话历史账目就对不上（今天的账按今天的价，以前的账要按当时的价）。

**代价**
每次调用多一次写库；token 估算有误差。

**能答哪些题**
成本怎么控 / token 怎么算 / 为什么要审计 / 企业级和 demo 的区别 / 可观测怎么做

**如果只能记一句**
> 记账要能算「这一次花了多少」，不是「这个月花了多少」。

## 卡 9｜聚合用规则，不用模型（告警系统）

**选了什么**
告警降噪用指纹 + 时间窗聚合（纯规则）。只有「判断是不是真攻击」才用模型。

**为什么不选别的**
三条理由：

- 聚合是**确定性任务**——同一批告警永远聚成同样事件，用模型既慢又不稳
- **规则可解释**——能说清「这两条为什么被合并」，模型说不清
- **98.7% 的降噪率是规则的功劳，我不拿它当模型效果讲**

**代价**
换 IP 打同一台机器会被拆成多簇（纯指纹的固有缺陷）。

**能答哪些题**
降噪率怎么算 / 为什么不用模型做聚合 / 规则和模型怎么分工 / 可解释性

**如果只能记一句**
> 把「确定的」交给规则，把「不确定的」交给模型——这个分工比选什么模型重要。

---

## 卡 10｜窗口状态从内存迁 Redis（告警系统）

**选了什么**
滑动窗口状态从进程内存迁到 Redis ZSet。

**为什么不选别的**
内存版两个硬伤：**重启就丢、多实例各数各的。**

我做了实验证明：灌 3 条同指纹告警 → 重启服务 → 再灌 2 条。

**内存版计数从 3 归零只剩 2，永远凑不到阈值 5 —— 这次攻击就漏了。**

为什么用 ZSet 不用 INCR：INCR+EXPIRE 是固定窗口（10:09:59 来 3 条、10:10:01 来 3 条，两个 key 都不足 5 就漏），ZSet 用时间戳做 score 才是真滑动窗口。

**代价**
性能掉了 139 倍（73 万次/秒 → 5271 次/秒）。但这是**正确性换性能，不是优化**。

**能答哪些题**
为什么迁 Redis / ZSet vs INCR / 性能和正确性怎么权衡 / 重启丢数据 / 多实例

**如果只能记一句**
> 判断标准是「这份数据丢了会怎样」——丢一次攻击就漏报，那它就不能只活在内存里。

# 第 3 章：被问到不会的怎么办

**这可能是全场最有用的四句话。**

| 情况 | 怎么说 |
|---|---|
| 完全没做过 | 「这块我没做过。我理解是 X，让我做会先 Y，您看对不对？」 |
| 做过但不深 | 「我做到的是「能跑通」这个程度，没深到源码层。」 |
| 概念记不清 | 「定义我说不准，但我项目里遇到过类似问题：……」 |
| 被质疑不是本人做的 | 「您随便挑一个函数问我。我能讲清为什么这么写、放弃了什么。」 |

**核心**：承认边界 + 展示理解 + 把判断权交回去。

# 第 4 章：临场（进门前 5 分钟）

## 4.1 四个万能句

| 场景 | 一句 |
|---|---|
| AI 用法 | 「我用 AI 做执行，不用 AI 做判断。样板代码交给它，架构和取舍我自己定。」 |
| 最大不足 | 「缺少协同开发的习惯。独立做久了会自己憋、文档按自己能看懂写、也没被 review 过。这三点我在改。」 |
| 代码归属 | 「代码不是我一字一句敲的，但架构、验收标准、对错判断是我做的。」 |
| 不会的题 | 「我没做过，我理解是 X，让我做会先 Y。」 |

## 4.2 三个数字

| 数字 | 什么 |
|---|---|
| 98.7% | 告警降噪率（**纯规则，不说成模型的功劳**） |
| 7875 / 8000 | 预算利用率 98.4% |
| 27 单测 + CI 六关 | 工程纪律 |

## 4.3 三句不能说

- ❌「我没实习经历，所以……」→ 直接讲你做过什么
- ❌「这个我不太清楚，我回去学」→ 改成「我没做过，我理解是 X」
- ❌「我在自学 AI」→ 改成「我做了三个项目，两个开源」

## 4.4 进门前默念

> 不需要全会。八项要求我中六项，缺口一个 Node.js——**六比八够了。**
>
> 承认边界不减分，面试官听到的是「可信」。
>
> 我也在看他们：试岗有没有钱、主营是什么、团队几个人。

**说话慢一点。紧张的人语速都会快。**
