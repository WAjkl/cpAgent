# 第二部分：按功能分类（面试时这样讲）

> 不要按"我学过什么语法"讲，要按"我做出什么功能"讲。
> 下面六类，每类都有**具体文件做证据**，被追问能说得出在哪。

## 2.1 Web 服务与 API（最大的一块）

**做了什么**：
- 用 **FastAPI** 写了三个服务的后端接口（告警系统六个接口、cpAgent 十几个、存储层十几个）
- 用 **Pydantic** 定义请求/响应模型，做参数校验（`Field(ge=1, le=5)` 这类约束）
- 接口文档自动生成（`/docs` 能点测试）

**证据**：`backend/server.py`（389 行）、`AlarmStore/app/main.py`（323 行）、`SecTriage/app/api.py`（188 行）

**能讲的技术点**：
> 「FastAPI 的好处是它把 Pydantic 校验和文档生成绑在一起了——我定义模型，参数错了自动 422，文档自动更新。所以我不用手写校验代码，前端也能直接照 `/docs` 写类型。」

## 2.2 异步与并发

**做了什么**：
- **`async / await`** 写异步接口
- **`asyncio`** 处理并发请求（告警系统从串行改并发，整体耗时 80.2s → 6.2s）
- 线程池跑阻塞任务（数据库查询这类同步操作）

**证据**：`SecTriage/app/pipeline.py`（203 行）、`app/resilience.py`（148 行）

**能讲的技术点**：
> 「Python 的 async 适合 I/O 密集——等数据库、等网络的时候让出控制权。但如果是 CPU 密集（比如大量计算），asyncio 没用，得用多进程或者交给别的服务。」

## 2.3 数据访问与连接管理

**做了什么**：
- **手写了一个数据库连接池**（不是用现成库）：没满就新建、满了排队、释放放回队列、连接坏了要把计数减回去

- SQLite 管三个库（证据库、长期记忆、审计）

**证据**：`AlarmStore/app/db.py`（142 行）、`backend/evidence.py`（158 行）、`backend/audit.py`（204 行）

**能讲的技术点**：
> 「连接池必须手写一遍才知道坑在哪。我的坑是：连接坏了要把计数减回去——不然网络抖一下，池就越用越小，最后卡死。」

## 2.4 LLM 集成与 Agent 循环

**做了什么**：
- **手写 ReAct 循环**（不用 LangChain）：想一步 → 调工具 → 看结果 → 再想，最多 12 步
- **LLM 可插拔**：抽象基类 + 三个实现（DeepSeek / Ollama / Mock）
- **工具注册表 + 白名单**
- 从 API 响应里提取 token 用量做成本归因

**证据**：`backend/agent_loop.py`（433 行）、`backend/llm.py`（268 行）、`backend/tool_registry.py`（241 行）

**能讲的技术点**：
> 「LLM 可插拔我是用一个抽象基类做的，规定必须有 `chat()`。好处是换模型改一行配置，测试时用 Mock 不花钱。
>
> 而且我在 `llm.py` 里做了个事：API 返回的 `usage` 字段本来被丢掉了，我把它接出来记进审计——这样能算清每次调用花多少钱。」

# 第三部分：「你 Python 熟不熟」怎么答（核心）

## 3.1 三层答法（推荐，这是最稳的）

> 「我分三层说。
>
> **第一层，能独立做东西——这层我确定。**
> 我用 Python 写过 FastAPI 后端、手写 ReAct 循环、手写数据库连接池、SSE 流式输出、MCP server、正则采集器，加起来一万多行，都跑起来过，也都踩过坑。
>
> **第二层，常用机制我能讲清用途和场景。**
> 装饰器、生成器、上下文管理器、`async/await`、GIL 是什么——这些我知道什么时候该用、为什么这么设计。
>
> **第三层，没到源码层。**
> CPython 的内存管理、GIL 的底层实现、协程调度器怎么写，我只有概念，没读过源码。
>
> 所以如果问"熟不熟"，我的回答是：**能干活这一层我确定，原理层我知道自己的边界在哪。**」

### 为什么这个答法好

| 层 | 效果 |
|---|---|
| 第一层给证据 | 一万行、能跑、踩过坑——**没法反驳** |
| 第二层给范围 | 不吹"精通"，说"知道什么时候用" |
| 第三层主动划线 | **这一句最值钱**——面试官会觉得你实在，而且是真懂才划得清 |

**绝大多数人会卡在第二层假装第三层也懂，然后被一个"那 GIL 具体怎么实现的"问穿。**

# 第四部分：Python 追问准备（八问）

> 每题给「答到什么深度」和「不会怎么兜」。**不用全背，扫一遍有个印象。**

## Q1 GIL 是什么？为什么有？

**能答**：
> 「GIL 是全局解释器锁，保证同一时刻只有一个线程执行 Python 字节码。
>
> 它存在是因为 CPython 的内存管理（引用计数）不是线程安全的，加锁最简单。代价是**多线程在 CPU 密集场景下没用**——四个线程也只能用一个核。
>
> 所以：I/O 密集型用多线程或 asyncio 有意义（等的时候会释放 GIL），CPU 密集型要用多进程。」

**不会兜**：「我知道它限制多线程并行，具体在 CPython 里怎么实现的，我没读过源码。」

## Q2 装饰器怎么实现的？

**能答**：
> 「装饰器本质是一个函数，接收一个函数、返回一个新函数。`@deco` 就是 `func = deco(func)` 的语法糖。
>
> 我在项目里用它做统一的事情，比如给 LLM 调用加审计——不用每个调用点都写一遍记录逻辑。」

**追问「带参数的装饰器呢？」**
> 「那就多套一层：外层接收参数返回装饰器，装饰器再接收函数。」

## Q3 生成器和迭代器有什么区别？

**能答**：
> 「迭代器是实现了 `__iter__` 和 `__next__` 的对象；生成器是**用 `yield` 写出来的迭代器**——写起来简单得多。
>
> 关键价值是**惰性求值**：不会一次性把所有数据算出来放内存。我处理 30 万行数据时就是分块 yield，不一次性读进内存。」

## Q4 async/await 什么原理？

**能答**：
> 「`async def` 定义的是协程。`await` 的作用是：**这里要等 I/O，先把控制权交回事件循环**，让它去跑别的协程，等 I/O 好了再回来。
>
> 所以它是**单线程并发**——靠切换而不是靠多核。适合 I/O 密集，不适合 CPU 密集。
>
> 我在告警系统里用它把逐条处理改成并发，整体耗时从 80 秒降到 6 秒。」

**不会兜**：「事件循环内部怎么调度协程的，我只知道概念。」

## Q5 上下文管理器（with）怎么用？原理？

**能答**：
> 「`with` 保证退出时一定执行清理——哪怕中间抛异常。用在数据库连接、文件、锁这些必须释放的资源上。
>
> 实现是 `__enter__` 和 `__exit__` 两个方法，或者用 `contextlib.contextmanager` 装饰一个生成器。」

## Q6 浅拷贝和深拷贝区别？

**能答**：
> 「浅拷贝只复制最外层，里面的嵌套对象还是共享的；深拷贝递归复制所有层。
>
> **踩过的坑**：用浅拷贝复制一个配置字典，改嵌套字段时把原对象也改了。」

## Q7 列表和元组的区别？（基础题，可能顺口问）

**能答**：
> 「列表可变、元组不可变。元组能做字典的 key（可哈希），列表不行。
>
> 实际影响：元组占内存更小、创建更快，所以固定不变的数据我用元组。」

## Q8 你怎么处理 Python 的性能问题？

**能答**（这题最能体现工程思维）：
> 「先分清是哪种慢。
>
> **I/O 慢**（等数据库、等网络）→ 用 asyncio 并发，或者连接池复用。我在告警系统里改成并发，80 秒降到 6 秒。
>
> **CPU 慢**（大量计算）→ 多进程，或者换算法/换语言。Python 在这块没优势，别硬扛。
>
> **数据库慢** → 这不是 Python 的问题，去 EXPLAIN 看索引。我的深分页优化就是这类——42 毫秒降到 3 毫秒，靠的是换分页方式不是换语言。
>
> 所以我的习惯是**先定位瓶颈在哪一层，再决定动不动 Python**。」
