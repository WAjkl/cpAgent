## 一、三行骨架（面试前只记这三行）

```
1. 前端先解析需求（不等后端）→ 乐观插两条消息 → 探活 → POST /chat
2. 后端 FastAPI 的 StreamingResponse 吐 SSE，前端 fetch + getReader 手写解析
3. 卡最久：SSE 切包 buffer + 中文 TextDecoder；且我这是分片回放不是真 token 流
```

**再加一句必须主动说的**：
> 我做的是 Electron 桌面端，但架构就是标准前后端分离——**换成 Web 部署只改一个后端地址**。

## 二、真实事实（答之前先对上号，别记错）

| 环节 | 实现 |
|---|---|
| 前端 | Electron 33 + React 18 + TypeScript 5.6 + Tailwind + **Zustand 5（persist）** |
| 后端 | FastAPI + `StreamingResponse(media_type="text/event-stream")` |
| 流式 | `fetch` + `resp.body.getReader()` + `TextDecoder({stream:true})`，**手写解析，没用 EventSource** |
| 分包 | 按 `\n\n` 切事件，`buffer` + `chunks.pop()` 保留半截 |
| 事件 | `status`（路由）/ `delta`（增量文本）/ `config`（配置单）/ `warn` / `done` |
| 分片 | 后端 chunk = 24 字符，`await asyncio.sleep(0.015)` |
| 降级 | `/health` 探活 `AbortSignal.timeout(1500)` → 不通走 `chatMock` 逐字模拟 |
| 状态 | 只 patch 命中的那条 message 对象，其余引用不变 |
| 持久化 | `persist` 落 localStorage，`partialize` 只存 4 个字段 |

**最容易记错的三个数字**：探活 **1.5 秒**、分片 **24 字符**、步数上限 **12**。

## 三、完整口语版（照着说，约 3 分钟）

> 「行，我按**用户点发送之后的时间顺序**讲。

### ① 前端先解析，不等后端

> 用户输入一句话点发送，第一件事**不是请求后端**，是前端先把这句话解析成结构化需求——我用正则把预算、用途、分辨率、排除项（比如「不要显示器」）抽出来。
>
> 为什么前端要解析一次？因为右边那个需求面板要立刻更新。用户看到「预算 8000、打游戏、2K」这几个标签变了，有即时反馈。**等后端返回再更新，要等好几秒。**

### ② 乐观插入两条消息

> 然后乐观插入两条消息：一条用户原文，一条**空的 assistant 占位**，状态标成 `streaming`。用户马上能看到消息进去了。

### ③ 探活 + 降级

> 接着先探活：发一个 `/health`，**1.5 秒超时**，不通就走本地 mock 分支，用假数据逐字模拟一遍流式。这是我做演示或者断网时的兜底，**不至于点完发送白屏没反应**。

### ④ 请求与流式解析

> 探活通过就 `POST /chat`。后端是 FastAPI，这个接口返回的不是普通 JSON，是 `StreamingResponse`，`media_type` 是 `text/event-stream`，也就是 SSE。
>
> 前端这边我**没用 EventSource**，用的是 `fetch` 加 `body.getReader()`。因为 **EventSource 只能发 GET，带不了 body**，而我要把整段对话和偏好传过去。

### ⑤ 两个卡了很久的坑（这段最值钱）

> 拿到 reader 之后手写解析：按两个换行切事件、认 `data:` 前缀、`JSON.parse`。这里有两个坑我卡了挺久：
>
> **第一个，一个 SSE 事件会被 TCP 切包**，你读到的一半是半个 JSON，直接 parse 就报错。所以得留一个 buffer，每次只处理完整的部分，最后半截留着等下一个包拼上。
>
> **第二个，`TextDecoder` 一定要开 `{stream: true}`**，不然中文这种多字节字符正好被切在两包之间，就出乱码。我一开始偶尔看到回答里有方块字，就是这个原因。

### ⑥ 事件处理与渲染性能

> 解析出来五种事件：`status` 是路由结果，`delta` 是文本增量，`config` 是配置单，`warn` 是警告，`done` 是结束。`delta` 收到就追加到那条 assistant 消息上。
>
> 这里**性能上有个点**：我只 map 替换那一条 message 对象，**其他消息对象的引用不动**。React 浅比较能跳过没变化的组件，不会整个消息列表重渲染。如果每来一个字就把整个数组深拷贝一遍，消息一多就明显卡。

### ⑦ 收尾与持久化

> 收到 `done` 把状态改完成，中间的 `config` 单独渲染成一张配置单卡片，跟文字分开。
>
> 刷新页面不丢记录，是因为状态在 Zustand 里，套了 `persist` 落 localStorage，但**只持久化会话列表、当前会话、主题这几个字段**，临时的流式状态不存。

### ⑧ 诚实交代卡点（一定要说）

> **卡最久的是 SSE 那两个坑**，切包和中文解码。
>
> 另外有个我得老实说：我现在这个流式**不是真正的 token 流**——Agent 要多步工具调用，最终答案得等整个循环跑完才能确定，所以现在是跑完之后按 24 个字符一段回放给前端，是个打字机效果。要接真流式，得等 LLM 那边开 stream 接口，边生成边往前端送。**我知道差距在哪，只是现阶段优先把链路跑通。**」

## 四、必被追问的五题（提前备好，答不上就白讲了）

### Q1｜「你为什么用 fetch 不用 EventSource？」

> EventSource 有两个硬限制：**只能 GET**，带不了请求体；**不能自定义 header**。我要 POST 一整段对话加偏好过去，所以只能用 fetch 手动读流。代价是得自己解析 SSE 格式，那正好就是我踩的那两个坑。

### Q2｜「流式过程中前端怎么知道出错了？」

> 分两种。**业务层错误**后端在 generator 里 catch 住，`yield` 一个 `warn` 事件，前端照常显示，主回答不受影响——比如配置单生成失败，但文字回答还在。
> **连接层错误**（后端崩了、超时断流）会直接抛到 fetch 那边，我在 `catch` 里把这条消息的状态改成 `error`，内容替换成错误提示加一句「请确认后端已启动」。**不会让用户看着一个永远转圈的 loading。**

### Q3｜「多个会话同时流式会串吗？」

> 不会串。每次请求的 handler 是闭包，**捕获了自己的会话 id 和消息 id**，patch 的时候按 id 精确匹配。切到别的会话，旧流还在往原来那条消息写，不会写到新会话里。
> **但有个真缺陷：同一会话连点两次发送，两条流会同时跑**，虽然写的是不同消息对象不会串，但白白烧两份 token。这块该做的是发送时禁用按钮，加请求去重。

### Q4｜「为什么做成 Electron，不做网页版？」**（这题必须答，JD 是 Web 岗）**

> 因为后端是本地 Python 服务，做成桌面端用户**双击就能用，不用部署服务器**，也不用管 CORS 和端口穿透——我的主进程里专门有一条转发通道就是干这个的。
> **但架构上就是标准前后端分离**：renderer 是 React + TS，后端是 FastAPI 出 REST + SSE，**换成 Web 部署本质只改一个后端地址**。所以这套东西迁到浏览器没有任何结构性障碍。

### Q5｜「如果现在加真流式，你要改哪？」

> 后端 `agent.run()` 现在是同步阻塞跑完才返回，得改成异步：LLM 那层开 `stream=True`，边拿 token 边 `yield`；Agent 循环也要改成 async generator，把「模型思考中」「正在调工具」这些中间状态作为新事件类型推给前端。
> 前端基本不用改，**因为我的解析层已经是按事件类型分发的，加一种事件只是多一个 case**。

## 五、两个必须主动交代的事（不说会被当成不懂）

### ① 主动说「这是分片回放，不是真 token 流」

**为什么必须主动说**：如果被问「用户多久能看到第一个字」，真实答案是**等整个 Agent 跑完**（十几秒）。你不说，被问出来就是「声称做了流式但其实是假的」；你主动说，就是「我知道流式的本质，也清楚自己的技术债」。

**一字不差的说法**：
> 「Agent 要多步工具调用，答案必须等循环结束才能确定，所以现在是分片回放。真流式需要 LLM 层开 stream、循环改成 async generator。」

### ② 主动把 Electron 翻译成 JD 听得懂的话

JD 要的是 Web 全栈（React/Vue + Node）。你是 Electron，**中间有个错配**，不主动解释，面试官会怀疑「他没做过 Web」。

**一句话解决**：Electron 只是外壳，**内核就是标准前后端分离**，迁 Web 只改后端地址。
