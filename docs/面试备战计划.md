# 第六部分：怎么判断"我学会了"

> 别用"我看完了"当标准，用这个：

## 三个自测标准

**① 60 秒测试**
随便指一个项目，你能连续说 60 秒，中间不断、不"嗯"、不看稿。

**② 追问测试**
让同学/家人问你一句"为什么"，你能接上第二层。**接不住就是没学会。**

**③ 外行测试**
用 30 秒向外行解释"为什么不让模型算价格"。讲不明白就是没真懂。

## 一个残酷但有效的检验

> **拿手机录一段 3 分钟的自我介绍 + 项目介绍，回放。**
>
> 你会发现三件事：语速比你想象的快、口头禅比你以为的多、"嗯"的位置正好是你没想清楚的地方。

**这一步比再读一万字有用。**

# 第七部分：心态（这条别跳过）

## 三句话

**① 你不需要全会**
八个 JD 要求里你中六个，缺口一个 Node.js。**六比八已经够了**，没有人全中。

**② 承认边界不减分**
「缓存只提升 7%」「没上线部署过」「没被 review 过」——这些话面试官听到的是**可信**，不是**不行**。

**③ 面试是双向的**
你也在看他们：试岗有没有钱、主营是不是教培、团队几个人。**问这些不丢人，是基本权利。**

## 最后一句

> 这场面试最重要的产出不是 offer，是**第一个真实反馈**。
>
> 你会被问到没准备的问题，会卡壳一两次，这都正常。**记录下卡在哪，下一场就不会卡在同一个地方。**
>
> 你手上的东西——三个能跑的项目、带测试带文档、GitHub 上都有提交记录——**比你以为的硬。放开了讲。**
