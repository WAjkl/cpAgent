# cpAgent 企业级改造方案

> 定位：从「个人装机顾问 demo」升级为「企业能采购的 AI 应用」。
> 本文所有判断基于 2026 年公开的行业调研数据，不是拍脑袋。

---

## 一、先看清差距：个人 demo 和企业级到底差在哪

### 1.1 行业现状（真实数据）

| 事实 | 数据 | 来源 |
|---|---|---|
| 企业 AI 成本超支 | **79%** 的企业在过去 12 个月经历过 | 网宿安全 UAG 行业调研 2026 |
| 成本预估偏差 | **85%** 偏差 >10%，近 **1/4** 偏差 >50% | 同上 |
| Agentic 项目死亡率 | Gartner 预测到 2027 年底 **40%+** 会因成本失控/价值不明/风控不足被取消 | Gartner |
| 审计追踪的地位 | **全链路审计追踪已被 Gartner 和 Forrester 共同列为企业级 AI 部署的基本门槛** | Gartner / Forrester |
| Agent 治理成熟度 | 只有 **21%** 企业有成熟的 Agent 治理模型，但 **74%** 计划部署 | Deloitte 2026 |
| 影子 AI | **78%** 的知识工作者在用未授权 AI 工具干活 | 2026 AI Adoption Report |
| 数据泄露 | 2026 上半年记录到 **42 起** 敏感数据被喂进公共大模型 | 同上 |
| RAG 幻觉率 | 金融/法律场景仍达 **4.5%**（尽管 64% 企业在用 RAG） | 同上 |
| Agent 延迟 | 跨部门多步任务平均 **18.5 秒** | 同上 |
| 合规压力 | EU AI Act 执法全面运行，**58%** 高管认为合规限制了 AI 规模化 | PwC 2026 |
| 中国企业态度 | **29%** 因治理/信任缺口暂缓 AI 规模化 | 埃森哲 2026 |

### 1.2 企业真正要的三本账

行业把企业 AI 的诉求归纳成三本账，这个框架比任何技术指标都好用：

| 账 | 企业问的问题 | 对应能力 |
|---|---|---|
| **成本账** | 这次调用花了多少？谁花的？超预算了吗？ | Token 归因、配额、预警、智能路由、语义缓存 |
| **安全账** | 密钥会不会泄露？数据会不会外流？ | 密钥托管、数据脱敏、内容安全、注入防护 |
| **责任账** | 这个结论谁让它出的？依据是什么？能复现吗？ | 全链路审计、可追溯、可解释、渐进式自主 |

### 1.3 一句话总结差距

**demo 证明「能跑通」，企业级证明「敢上线」。**
两者的分界线不是功能多少，而是：**出了问题能不能定位、花了多少钱能不能算清、做错了决定谁来负责。**

## 二、cpAgent 现状盘点

### 2.1 已经有的（比多数学生项目强的地方）

| 能力 | 具体实现 | 企业视角的价值 |
|---|---|---|
| 确定性拼装 | 配置单由算法拼，模型只出参数不碰价格 | **架构上消除幻觉**，这是最难做对的一层 |
| 价格溯源 | 每条带来源 + 抓取时间，过期标 expired，估算进 warnings | 责任账的雏形 |
| 工具白名单 | ToolRegistry + 参数校验 | 安全账的一部分 |
| 三道闸 | 步数 12 / token 预算 / 重复调用检测 | 成本账的雏形 |
| MCP 协议 | stdio 三工具 | 可被外部系统集成 |
| LLM 可插拔 | DeepSeek / Ollama / Mock 切换 | 模型治理的基础 |
| 多轮记忆 | longterm_memory.db | 体验层 |

| 企业要求 | 现状 | 缺口等级 |

## 三、改造方案（按优先级）

### P0-1｜审计日志 + 成本归因（一次解决成本账和责任账）

**企业痛点**：79% 企业成本超支，且「模型调用不可见、成本核算不清、责任难以追溯」。全链路审计是 Gartner 认定的准入门槛。

**做什么**：
```
每次调用写一条审计记录（SQLite）：
  trace_id / session_id / user_id / 时间
  model / prompt_tokens / completion_tokens / cost_cny
  工具调用序列（调了哪个工具、参数、返回码、耗时）
  最终输出摘要 + 是否人工确认
```

**为什么这一条最值**：同一份数据同时回答三个问题——花了多少（成本账）、谁花的（成本账）、为什么这么答（责任账）。

**工作量**：半天。加一张表 + 一个装饰器包住 LLM 调用和工具调用。

**面试怎么讲**：
> 「企业最怕的不是模型不够聪明，是调用不可见。我加了一层审计中间件，每次调用落一条记录，能算清这次会话花了多少钱、调了哪些工具、为什么给出这个结论。这是 Gartner 说的企业级准入门槛。」

---

### P0-2｜渐进式自主三档（从"全自动"到"可控自动"）

**企业痛点**：Deloitte 说只有 21% 企业有成熟的 Agent 治理模型。核心手段就是**渐进式自主**：人类批准 → 人类知会 → 完全自主。

**做什么**：
```
按动作风险分三档：
  · 只读操作（查硬件库、查价格）      → 自动执行
  · 可逆写操作（生成配置单、存草稿）  → 自动执行 + 事后通知
  · 不可逆/高金额（下单、改预算）     → 必须人工确认
```

**为什么这一条聪明**：你告警系统里的「三档路由（置信度 <0.8 转人工）」是同一个设计模式。**一套思路用在两个项目上，说明你抽象出了方法，不是碰巧做对。**

**工作量**：半天。加一个 `risk_level` 字段 + 确认回调。

**面试怎么讲**：
> 「Agent 落地最难的不是能力，是边界。我给它做了三档自主：只读直接跑、可逆的跑完通知、不可逆的必须人批。这跟我在告警系统里做的三档路由是同一个模式——置信度不够就转人工。」

---

### P0-3｜评测集 + 门禁（证明"改坏了能发现"）

**企业痛点**：幻觉率 4.5% 仍偏高；更关键的是**改了提示词或换了模型，没人知道是变好还是变坏**。

**做什么**：
```
30 条评测用例（覆盖典型需求 + 边界 + 对抗）
指标：配置单合法性、预算偏差、工具调用正确率、幻觉率
CI 里跑，指标跌出区间直接红
```

**为什么必须做**：这是**模型治理**的地基。没有它，后面所有"换模型""调提示词""灰度"都不敢动。

**工作量**：一天（写用例最花时间）。

**面试怎么讲**：
> 「AI 项目最难的不是让它对一次，是保证改完之后还对。我建了 30 条评测集，接进 CI 做门禁——指标跌出区间流水线直接红。没有这个，换模型和调提示词都是赌博。」

---

### P1｜密钥托管 + 数据脱敏（安全账）

**企业痛点**：42 起敏感数据泄露进公共模型；78% 员工在用未授权 AI 工具。

**做什么**：
- 密钥不写 `.env` 明文，改成启动时从系统凭据管理器/环境变量注入，代码里只引用句柄
- 输入侧做脱敏：手机号、身份证、详细地址 正则替换后再送模型
- 输出侧做二次校验：确认脱敏占位符被还原

**工作量**：半天。**这一条特别适合当面讲**，因为它体现"我知道数据不能随便喂"。

---

### P1｜智能路由 + 语义缓存（成本账进阶）

**企业痛点**：一刀切用大模型，简单任务付过剩算力溢价。

**做什么**：
- 路由：意图解析用便宜模型（或规则），只有配置生成才用大模型
- 缓存：相同需求（归一化后）直接命中历史配置，省一次完整调用

**实测数据可以自己做**：同一批 50 条需求，开关缓存对比 token 消耗和延迟。

---

### P1｜结构化可观测

**做什么**：把 print 换成结构化日志（JSON lines），加三个指标：每次会话 token、工具调用成功率、端到端延迟 P50/P95。**能出图就行**，不需要上 Prometheus。

---

### P2｜多租户 / SSO / 灰度（能讲不做）

这些学生项目做不动，但**必须知道为什么需要**：
- 多租户：不同部门的数据隔离
- SSO：员工离职权限自动回收
- 灰度：新版本先给 5% 用户，指标不跌再全量

面试被问就答：「这几块我知道是企业必需的，但以我的场景做不了真实验证，我只能讲清楚设计和取舍。」——**比假装做过强。**

---

## 四、建议的落地顺序

| 顺序 | 做什么 | 为什么这个顺序 |
|---|---|---|
| 1 | **审计 + 成本归因** | 一次解决两本账，代码量最小，面试最能用 |
| 2 | **评测集 + 门禁** | 后面所有改动的安全网，没有它不敢动模型 |
| 3 | **渐进式自主三档** | 概念最亮，且能复用告警系统的设计 |
| 4 | 密钥托管 + 脱敏 | 安全账，成本低 |
| 5 | 智能路由 + 缓存 | 有实测数据支撑，能讲优化故事 |
| 6 | 结构化可观测 | 收尾，让整个东西"看起来像生产系统" |

**做完 1-3，cpAgent 的定位就从「学生项目」变成「有治理意识的小型生产系统」。**

---

## 五、改造后怎么讲这个项目（一句话版本）

> 「这不是一个装机 demo。它有三层企业级设计：
> **第一层**，从架构上消除幻觉——配置单是算法拼的，模型不碰价格；
> **第二层**，可审计可归因——每次调用都落库，能算清花了多少钱、为什么给这个结论；
> **第三层**，渐进式自主——只读直接跑、可逆的跑完通知、不可逆的必须人批。
> 这三层对应企业落地最关心的成本账、安全账、责任账。」
